# Pay Theory docs

This repo is the Docusaurus 3 site for Pay Theory's API and SDKs. Guides live in `docs/`, a lab (preview) copy lives in `versioned_docs/version-lab/`, and the API reference pages are generated from `graphql/api.graphql` plus the request and response examples in `graphql/examples/`.

This skill is the current source of truth for how docs are written here. Where CLAUDE.md, older pages or memory disagree with it, follow the skill.

## Every task

Read [references/voice.md](references/voice.md) before writing any sentence a reader will see: page prose, admonitions, table descriptions, changelog entries, example names and descriptions. Run your draft through its cut list before you finish.

Then follow the branch for the task.

## Writing or editing a page

1. Read one or two sibling pages in the same directory and match them.
2. Write the page following [references/page-style.md](references/page-style.md): frontmatter, headings, admonitions, Tabs, code blocks, tables, links.
3. New file or directory: register it in `sidebars.js` and add a `_category_.json`. Details and formats are in [references/repo-mechanics.md](references/repo-mechanics.md).
4. Ask the user whether to mirror the change to lab. Lab sometimes differs on purpose, so check the lab file before overwriting it. Mirroring means the file under `versioned_docs/version-lab/` and its entry in `versioned_sidebars/version-lab-sidebars.json`.
5. After structural changes (new files, sidebar edits, components), run `npm run build`. It catches broken MDX, links and sidebar ids.
6. Commit as described under Commits.

Done when the page reads clean against voice.md, navigation shows it, the user has decided on lab, and the build passes.

## Adding or changing operation examples

Read [references/operation-examples.md](references/operation-examples.md) in full. It covers the file shape, the rules (self-contained, variables match the query, captured responses, confirmed behavior, access notes, naming) and the sample data.

Done when:

- `python3 .claude/skills/pay-theory-docs/scripts/lint_examples.py` reports no errors and you've read each warning,
- `npm run graphql:generate:all` has regenerated main and lab, and `lint_examples.py --check-generated` reports both in sync,
- anything you couldn't confirm is listed as a question in the PR description.

## Reviewing a docs PR

Follow [references/reviewing.md](references/reviewing.md). It pins down the diff (including stacked PRs), runs the lint and sync checks, builds the card-by-card review page from `assets/review-page.html`, and turns the reviewer's verdicts into a PR comment. Post nothing to GitHub until the reviewer approves the comment.

## Generated files

`docs/api/**` operation and type pages, `docs/api/_data/*.json` and their lab copies, `static/llm-docs/` and the agent-skill output are generated by `npm run graphql:generate:all` (also run by `prestart` and `prebuild`). Edit the sources (`graphql/api.graphql`, `graphql/examples/`, `graphql/intro_docs/`) and regenerate. Never hand-edit the output. The agent-facing artifacts (`llms.txt`, agent index, Markdown routes) have their own skill, `pay-theory-agent-docs`.

## Commits

Emoji, conventional type and scope, in the voice of voice.md:

```
📝 docs(online-payments): add custom fees guide
```

- Docs work is `📝 docs(<scope>): …`. New features can be `✨ feat(docs): …`. Scopes are feature names: `online-payments`, `js-sdk`, `apple-pay`, `google-pay`, `wallet`, `changelog`, `api`.
- The pre-commit hook runs `prettier:fix`, `lint:fix` and `check-ts`. It may reformat `sidebars.js`, which is expected. `sidebars.js` is plain JS, so type helpers with JSDoc, not inline TypeScript.
- Stage only files for this change. Leave local artifacts like `.plans/` out.
