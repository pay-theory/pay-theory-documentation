# Pay Theory Agent Docs Maintenance Skill

Handles updates to agent-facing documentation artifacts whenever docs content,
navigation, or GraphQL API generation changes. Use this skill alongside
`.claude/skills/pay-theory-docs` (which covers prose style, sidebar conventions,
and `_category_.json` patterns).

## Trigger conditions

Use this skill when you are:
- Adding, moving, or removing docs pages under `docs/` or `versioned_docs/`
- Changing sidebar structure in `sidebars.js` or `versioned_sidebars/`
- Regenerating GraphQL API docs via `graphql-docs.config.js`
- Touching `static/robots.txt`, `static/llms.txt`, or any `llm-docs` artifact
- Reviewing agent discoverability, sitemap, or LLM indexes

## What is generated vs. hand-authored

### Hand-authored (edit these directly)
- `docs/**`, `versioned_docs/version-lab/**` — doc content
- `sidebars.js`, `versioned_sidebars/version-lab-sidebars.json` — navigation
- `static/robots.txt` — robots crawl rules
- `agent-docs.config.js` — section definitions, topic index groupings, API skill paths

### Generated by prebuild (`npm run graphql:generate`)
- `static/llm-docs/**` — GraphQL API Markdown docs
- `static/llms.txt` — API-only LLM index (overwritten in postbuild by the full version)
- `docs/api/**`, `versioned_docs/version-lab/api/**` — GraphQL API doc pages
- `docs/api/agent-skills/`, `versioned_docs/version-lab/api/agent-skills/` — public API skill packages

### Generated by postbuild (`npm run build` → `postbuild`)
- `build/llm-docs/markdown-routes-manifest.json` — manifest of all Markdown routes
- `build/llm-docs/source/**` — normalized non-API Markdown source copies
- `build/llm-docs/agent-index.json` — enriched route catalog (title, version, section)
- `build/llms.txt` — expanded LLM entry point covering all doc sections
- `build/llms-full.txt` — complete list of all Markdown-accessible routes
- `build/llm-docs/indexes/guides.md`, `sdk.md`, `api.md`, `lab.md` — topic indexes
- `build/sitemap.xml` — generated by Docusaurus
- `build/robots.txt` — copied from `static/robots.txt`

**Never hand-edit files under `build/`.** They are overwritten on every build.

## Maintenance workflow

After any docs, sidebar, or GraphQL generation change:

```sh
npm run build
npm run agent-docs:check
```

Review the output:
- `build/sitemap.xml` — verify current doc routes appear
- `build/robots.txt` — verify `Sitemap:` URL is correct
- `build/llms.txt` — verify all sections are represented
- `build/llms-full.txt` — verify route count looks right
- `build/llm-docs/agent-index.json` — spot-check a few entries
```

`agent-docs:check` exits non-zero and identifies the stale/missing artifact and
the fix command. It can run without network access.

## Artifact config

To add a new curated section to `llms.txt` (e.g. a new top-level docs area):

1. Edit `agent-docs.config.js` → `sections` array.
2. Set `routePrefix` (or `routeExact`) to match the new routes.
3. Set `representativeRoute` to a stable entry-point URL.
4. Run `npm run build` to regenerate.

To add a new topic index (e.g. a `webhooks.md` breakdown):

1. Edit `agent-docs.config.js` → `topicIndexes` array.
2. Set `routePrefixes` to match the routes you want included.
3. Run `npm run build`.

## Live vs Lab routing

- Live routes: `/docs/**` (excluding `/docs/lab/**`)
- Lab routes: `/docs/lab/**`

`agent-index.json` labels every entry with `"version": "live"` or `"version": "lab"`.
`llms.txt` includes the default version guidance at the top.
Always confirm Live vs Lab routing is intentional before committing changes.

## Markdown negotiation

Any `/docs/**` URL serves Markdown (instead of HTML) when the request includes:
- `Accept: text/markdown`
- `x-format: md` (or other `x-*` markdown headers)

Direct Markdown URLs are always accessible:
- `/llms.txt`, `/llms-full.txt`
- `/llm-docs/**`
