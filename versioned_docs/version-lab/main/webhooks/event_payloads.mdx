# Webhook events

This page lists every event Pay Theory sends, with a sample body for each. The samples follow real deliveries, with the values replaced by sample data.

For the request headers and delivery rules, see [How webhooks work](overview).

***

## Reading payloads

`payload` is the record as Pay Theory stores it, not the GraphQL type. A few rules hold for every event:

- Amounts in payment records are integers of cents, such as `2500` for $25.00. `SETTLEMENT` and `FUNDING_TRANSFER` amounts are strings of cents, such as `"2500"`.
- Flags such as `is_active` and `is_settled` are `true` or `false`.
- Every field is present, and unset fields are `null`.
- Keys are in alphabetical order.
- `metadata` is a JSON string. Parse it to read your values.
- Pay Theory may add fields. Ignore fields you don't use.
- Some records also send a `DELETED` subtype when they're removed, such as a deleted invoice. Handle any subtype you don't expect without failing.

Every payload has `merchant_uid`. To get the latest state of a record, query it with the ID in the payload.

***

## TRANSACTION

Sent when a payment, refund or reversal is created (`CREATED`), and when its status, fees or settlement change (`UPDATED`). A card payment usually sends `CREATED` when it's approved, then `UPDATED` when it settles.

| Key | type | description |
|---|---|---|
| `transaction_id` | String | ID of the transaction. |
| `transaction_type` | String | `DEBIT` for a payment, `REVERSAL` for a refund, `ACH_RETURN` for a returned ACH payment, `FAILURE` for a declined payment. |
| `status` | String | Such as `PENDING`, `SETTLED`, `FAILED`, `REFUNDED`, `RETURNED` or `VOIDED`. See [Understanding transaction statuses](../after_payments/understanding_transaction_statuses). |
| `gross_amount` | Int | Amount charged, in cents, including fees. |
| `fees` | Int | Fees, in cents. |
| `net_amount` | Int | Amount the merchant receives, in cents. |
| `refunded_amount` | Int | Amount refunded so far, in cents. |
| `fee_mode` | String | `MERCHANT_FEE` or `SERVICE_FEE`. |
| `is_settled` | Boolean | `true` once the transaction is in a settlement. |
| `settlement_batch` | String | Settlement batch number, once settled. |
| `reference` | String | Your reference for the payment. |
| `account_code` | String | Your account code for the payment. |
| `metadata` | String | JSON string of the metadata you sent with the payment. |
| `failure_reasons` | Array | Why the payment failed, for failed payments. |
| `payment_method` | Object | The payment method token used, with its `payor`. |
| `merchant` | Object | The merchant that took the payment. |
| `invoice` | Object | The invoice paid, if any. |
| `recurring` | Object | The recurring payment, if any. |

## AUTHORIZATION

Sent when you create an authorization (`CREATED`), and when it changes, such as when it's captured or canceled (`UPDATED`).

| Key | type | description |
|---|---|---|
| `authorization_id` | String | ID of the authorization. |
| `status` | String | `SUCCEEDED` when approved, `FAILED` when declined, `CANCELED` when canceled. |
| `amount` | Int | Amount authorized, in cents. |
| `fees` | Int | Fees, in cents. |
| `captured_amount` | Int | Amount captured, in cents. `null` until captured. |
| `transaction_id` | String | The transaction created by the capture. |
| `sale_id` | String | Groups the authorization with its transaction. |
| `expiration_date` | String | When the authorization expires if not captured. |
| `failure_reasons` | Array | Why the authorization was declined. |
| `payment_method` | Object | The payment method token used, with its `payor`. |

## SPLIT_FUNDING

Sent when part of a transaction is split to another merchant (`CREATED`). See [Split transactions](../online_payments/split_transactions).

| Key | type | description |
|---|---|---|
| `id` | String | ID of the split. |
| `transaction_id` | String | The transaction the split came from. |
| `amount` | Int | Amount sent to the receiving merchant, in cents. |
| `merchant` | Object | The merchant that receives the split. |
| `payment_method` | Object | The payment method token the payor used. |
| `settlement_batch` | String | Settlement batch the split was paid in, once settled. |

## INVOICE

Sent when an invoice is created (`CREATED`), when it changes, such as when it's paid (`UPDATED`), and when it's deleted (`DELETED`).

| Key | type | description |
|---|---|---|
| `invoice_id` | String | ID of the invoice. |
| `status` | String | `NOT_PAID`, `PARTIALLY_PAID` or `PAID`. |
| `invoice_amount` | Int | Amount due, in cents. |
| `total_paid_amount` | Int | Amount paid so far, in cents. |
| `invoice_name` | String | Invoice name. |
| `due_by` | String | Due date, if set. |
| `payor` | Object | The payor the invoice is for. |
| `settings` | Object | Accepted payment methods and security settings. |

## SETTLEMENT

Sent when Pay Theory creates a settlement batch for a merchant (`CREATED`), and when the batch changes, such as when its funds are sent (`UPDATED`).

| Key | type | description |
|---|---|---|
| `settlement_batch` | String | Batch number. Transactions in the batch have the same `settlement_batch`. |
| `status` | String | `PENDING` until the funds are sent, then `SUCCEEDED`. |
| `settlement_date` | String | Day the batch covers. |
| `transfer_date` | String | When the funds were sent. `null` until then. |
| `gross_amount` | Int | Total of the batch's transactions, in cents. |
| `total_fees` | String | Fees in the batch, in cents. |
| `total_adjustments` | String | Refunds, returns and disputes in the batch, in cents. |
| `net_amount` | Int | Amount paid to the merchant, in cents. |
| `transaction_debit_count` | String | Number of payments in the batch. |
| `transaction_reversal_count` | String | Number of refunds in the batch. |
| `transaction_dispute_count` | String | Number of disputes in the batch. |

## MERCHANT

## PAYMENT_METHOD

Sent when a payment method token is created (`CREATED`), and when it changes, such as when it's deactivated (`UPDATED`).

| Key | type | description |
|---|---|---|
| `payment_method_id` | String | ID of the payment method token. |
| `payment_type` | String | `CARD`, `ACH` or `CASH`. |
| `last_four` | String | Last four digits of the card or account number. |
| `card_brand` | String | Card brand, for cards. |
| `exp_date` | String | Card expiration as `MMYY`, for cards. |
| `bank_account_type` | String | Account type, for ACH, such as `PERSONAL_CHECKING`. |
| `bank_code` | String | Routing number, for ACH. |
| `is_active` | Boolean | `false` once the token is deactivated. |
| `payor` | Object | The payor that owns the payment method. |
| `metadata` | String | JSON string of the payment method's metadata. |
