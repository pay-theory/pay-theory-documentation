# PayTheory Fragment

The `PayTheoryFragment` is the core UI component of the Pay Theory Android SDK. It handles the display and management of payment form fields, validation states, and payment processing.

## Overview

The fragment dynamically displays payment fields based on the configured payment method type and requirements. It manages field validation and state tracking for all payment types.

## Usage

Add the fragment to your layout:

```xml
<fragment
    android:id="@+id/payTheoryFragment"
    android:name="com.paytheory.android.sdk.fragments.PayTheoryFragment"
    android:layout_width="match_parent"
    android:layout_height="wrap_content" />
```

## Dynamic Payment Fields

The fragment automatically displays different input fields based on the `paymentMethodType` set in your configuration:

### Card Payment Fields
When `paymentMethodType = PaymentMethodType.CARD`:
- Card Number field
- Expiration Date field
- CVV field
- Postal Code field (if `requireBillingAddress = true`)
- Billing Address fields (if `requireBillingAddress = true`)
  - Street Address
  - City
  - State
  - ZIP Code

### ACH/Bank Payment Fields
When `paymentMethodType = PaymentMethodType.BANK`:
- Account Number field
- Routing Number field
- Account Type selector (Checking/Savings)
- Account Name field (if `requireAccountName = true`)

### Cash Payment Fields
When `paymentMethodType = PaymentMethodType.CASH`:
- Payer Name field
- Contact Information field (email or phone)

Additional fields may appear based on configuration properties:
- Account Name field appears when `requireAccountName = true`
- Billing Address fields appear when `requireBillingAddress = true`

## Accessible Properties

### Payment States

The fragment provides access to validation states for different payment methods:

#### Card Payment State
```kotlin
val card: CardState
```
Tracks validation state for credit/debit card fields:
- `cardFieldValid`: Boolean - Card number validation
- `expFieldValid`: Boolean - Expiration date validation  
- `cvvFieldValid`: Boolean - CVV code validation
- `zipCodeFieldValid`: Boolean - ZIP/Postal code validation
- `cardFieldsValid`: Boolean - Overall card fields validation

#### ACH Payment State
```kotlin
val ach: ACHState  
```
Tracks validation state for ACH/bank account fields:
- `accountNumberValid`: Boolean - Account number validation
- `routingNumberValid`: Boolean - Routing number validation
- `accountTypeValid`: Boolean - Account type validation
- `bankFieldsValid`: Boolean - Overall ACH fields validation

#### Cash Payment State
```kotlin
val cash: CashState
```
Tracks validation state for cash payment fields:
- `cashNameFieldValid`: Boolean - Payer name validation
- `cashContactFieldValid`: Boolean - Contact info validation
- `cashFieldsValid`: Boolean - Overall cash fields validation

## Public Methods

### configurePayment

Configures the fragment for processing a payment:

```kotlin
fun configurePayment(configuration: PayTheoryConfiguration)
```

### configureTokenize

Configures the fragment for tokenizing a payment method:

```kotlin
fun configureTokenize(configuration: PayTheoryConfiguration)
```

### transact

Initiates the payment transaction:

```kotlin
fun transact()
```

### tokenize

Initiates payment method tokenization:

```kotlin
fun tokenize()
```

### clearFields

Clears all input fields and resets validation states:

```kotlin
fun clearFields()
```

The fragment supports three payment method types:

```kotlin
companion object {
    const val PAYMENT_CARD = "card"

}
```

## Example Implementation

```kotlin
class PaymentActivity : PayTheoryMerchantActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_payment)

        val payTheoryFragment = supportFragmentManager
            .findFragmentById(R.id.payTheoryFragment) as PayTheoryFragment

        // Monitor validation states
        payTheoryFragment.card.cardFieldsValid // Check if card fields are valid
        payTheoryFragment.ach.bankFieldsValid  // Check if ACH fields are valid
        payTheoryFragment.cash.cashFieldsValid // Check if cash fields are valid

        // Configure payment
        val config = PayTheoryConfiguration(
            apiKey = getString(R.string.api_key),
            paymentMethodType = PaymentMethodType.CARD
        ).apply {
            requireBillingAddress = true  // Will show billing address fields
            requireAccountName = true     // Will show account name field
        }
        payTheoryFragment.configurePayment(config)
    }
}
```

## Important Notes

- The fragment automatically handles field validation and state management
- Payment fields are displayed dynamically based on the configured payment method type
- All validation states are updated in real-time as users enter information
- The fragment must be configured before attempting any payment operations
- Clear fields using `clearFields()` after successful transactions
- Field validation rules and states are managed automatically
- Input masking and formatting is handled automatically for sensitive fields

For more information about configuration options, see [Configure Payment](./functions/configure_payment) and [Configure Tokenize](./functions/configure_tokenize).
